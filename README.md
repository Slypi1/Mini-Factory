Архитектура

Игровая логика разделена на сервисы, состояние и компоненты Unity.

Конфигурация: GameConfig и MachineConfig хранят параметры игры и экономики.

Состояние: FactoryState и MachineState содержат данные текущей игровой сессии.

Экономика: EconomyService рассчитывает производительность и стоимость улучшений.

Фабрика: FactoryService отвечает за открытие и улучшение машин, а также изменение баланса.

Производство: ProductionService рассчитывает доход от производства.

Boost: BoostService управляет временным множителем производства.

Офлайн-прогресс: OfflineProgressService рассчитывает доход за время отсутствия игрока.

Сохранение: ISaveService определяет интерфейс сохранения, SaveService использует PlayerPrefs и JSON-сериализацию.

UI: FactoryUI и MachineCardUI отображают игровое состояние и обрабатывают действия игрока.

Покупки: IAPManager отвечает за инициализацию магазина, получение товаров, покупки и подтверждение заказов.

Аналитика: IAnalyticsService определяет интерфейс отправки событий, DebugAnalyticsService выводит события в Unity Console.

нутриигровые покупки

Реализована покупка расходуемого товара с идентификатором coins_pack_small.

При успешной покупке игрок получает настроенное количество внутриигровой валюты. Используется Unity In-App Purchasing 5.4.4.

Аналитика

В текущей реализации используется отладочный провайдер, который выводит события в Unity Console.

Основные игровые события:

game_started

machine_unlocked

machine_upgraded

boost_started

boost_finished

offline_income_applied

События покупок:

purchase_succeeded

purchase_failed

Дополнительно логируются события жизненного цикла IAP: инициализация магазина, получение списка товаров, ошибки загрузки и недоступность магазина или товара.

Тестирование

Unit-тесты покрывают базовую игровую логику, включая инициализацию фабрики, расчёты производства и поведение Boost.

Для запуска тестов откройте Window → General → Test Runner в Unity Editor.

Во время разработки были успешно выполнены шесть unit-тестов.

Сборка под Android

Откройте File → Build Profiles или соответствующий интерфейс настроек сборки в используемой версии Unity.

Выберите Android в качестве целевой платформы.

Убедитесь, что необходимые модули Android Build Support установлены через Unity Hub.

Проверьте, что основная игровая сцена добавлена в список сцен сборки.

Настройте идентификатор приложения и остальные необходимые параметры Player Settings.

Выполните сборку и проверьте её на Android-устройстве или эмуляторе.

Сборку под целевое устройство необходимо проверить перед финальной сдачей проекта.

Ограничения

Сохранение хранится локально через PlayerPrefs; облачная синхронизация не реализована.

Отладочная аналитика выводит события локально; удалённый аналитический сервис не подключён.

Проект не содержит production-конфигурации магазина и реальных платёжных данных.

Firebase Remote Config и удалённая аналитика не подключены.

Офлайн-доход ограничен заданной максимальной продолжительностью.

Для production-использования потребуются дополнительные проверки ошибок магазина, повреждённых сохранений и граничных случаев экономики.
